# 播放、长列表与窗口性能

## 验证哪些行为

| 场景 | 实现 | 检查重点 |
| --- | --- | --- |
| 长播放队列 | 以 53px 行高和额外可视行做虚拟化 | 700 首以上仍可到末首，拖动与高亮使用真实队列位置 |
| 长篇歌词 | 少于 96 行使用普通文档流，其余按每组 16 行挂载与估算高度 | 跳到后半段、切换翻译、阅读或拖动时当前行和键盘焦点可恢复 |
| 连续切歌 | 取消旧动画和旧请求，保留新选择 | 快速切换、播放后立刻暂停、关闭全屏时旧回调不会重新打开页面 |
| 封面和频谱 | 列表按显示尺寸加载平台缩略图，失败后回退原图。横幅可见并有实频时才加载点阵 | 播放时向下滚出整个横幅，检查局部频谱、点阵与加载动画停下。滚回后跟随当前音乐 |
| 原生表面 | 设置和小窗隔离，按范围执行窗口与存储命令 | 同一控件在毛玻璃、液态玻璃、不同 DPI 与窄窗口下可用 |

这些是实现参数与检查场景。帧率、内存占用与启动耗时要在指定硬件和相同曲单上测量。[队列实现](../src/components/player/QueueList.vue) · [歌词窗口](../src/services/player/lyric-window.js)

## 在浏览器中复现

打开本机 Vite 服务（默认地址为 `http://127.0.0.1:1420`）。在同一首歌、同一窗口大小与滚动位置下切换两种材质。加载或取消播放时，观察内容区、播放按钮和键盘焦点。

可运行 `node --test scripts/banner-perf.test.mjs scripts/cover-thumbnail.test.mjs scripts/public-playlists.test.mjs` 检查频谱调度、缩略图地址和公开歌单的分批显示。频谱测试使用模拟音频和帧时钟。实际播放时分别打开、关闭底栏频谱再滚动首页，确认关闭底栏且横幅不可见时不再采样，滚回横幅后恢复。

## 原生验收

打开桌面包，检查 Windows 10 阴影透明区、多个显示器的工作区边缘与从托盘恢复，在本机输出设备上试听 EQ。记录动态效果设置、系统缩放与曲目标识，以便在另一台机器上复现。[开发文档](DEVELOPMENT.md) · [桌面操作](desktop.md)
